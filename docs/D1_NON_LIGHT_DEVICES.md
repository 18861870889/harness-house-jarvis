# D1 非灯具设备动作

2026-10-10，家庭沙盒语义契约 **v3.1**。这是 Alpha 沙盒能力，不是主应用发布版本。HA 只读参考，所有控制只修改独立内存副本；不修改原户型、设备名称或回路分配。

## 支持范围

| 设备 | 接口存在且策略允许时的动作 | 边界 |
| --- | --- | --- |
| 空调 | 开关、目标温度 | 温度必须有可靠范围与步长；开机并设温的复合要求暂时反问 |
| 风扇 | 开关、风速百分比、摇头开关 | 依据主 fan 实体，不改指示灯/提示音；检查百分比步长 |
| 窗帘 | 开关、开度百分比、停止移动 | 依据 cover 接口，不把电机反向开关当作开关窗帘 |
| 电视/音箱 | 原生或红外开关、播放/继续、暂停、停止、音量、静音、已接入换台按钮 | 停止、暂停、关电源分开；没有停止接口时询问是否暂停；不支持任意歌曲/节目搜索 |
| 晾衣杆 | 升起、降下、停止、接口提供的位置百分比 | 需要真实 cover 或已识别动作按钮；单纯电源开关不是升降接口 |
| 猫粮机 | 按设备配置的单次份量投喂一次 | 必须精确确认；不改计划、不猜克数、不自动校准/重置 |
| 扫地机器人 | 开始清扫、停止清扫、回充 | 需要 vacuum 能力；当前模型只显示状态，不模拟真实清扫路线 |
| 传感器/监控状态 | 已接入状态查询 | 只读；场景人物不伪造检测状态，也不提供点击改状态 |

按 [HA climate](https://developers.home-assistant.io/docs/core/entity/climate/)、[fan](https://developers.home-assistant.io/docs/core/entity/fan/)、[cover](https://developers.home-assistant.io/docs/core/entity/cover/)、[media player](https://developers.home-assistant.io/docs/core/entity/media-player/)、[vacuum](https://developers.home-assistant.io/docs/core/entity/vacuum/) 的公开实体功能与服务映射。可选服务来自 `supported_features`，数值来自绑定属性/能力证据，不按设备名推断。例如音箱的暂停功能位与停止功能位不同。

## 决策与安全

```text
原话 + 可信来源 -> D1 意图字段 -> HCM 目标绑定
  -> 从该设备接口/策略派生最多 15 个动作及 unsupported
  -> D1 选择具体动作 -> 编译有限 operation 和参数
  -> 范围/步长/单位、在线状态、权限和精确确认
  -> HCM / 服务模拟 -> 内存 adapter 再核验 -> 状态字段回读
  -> 三维场景 + 设备详情 + 决策轨迹
```

模型选择候选 ID，不生成任意 HA 服务。运行时动作值示例：`{ "operation": "set_speed", "argument": 50 }`。它编译为已有 fan 接口的 `set_percentage`，而不是修改同设备上的其他开关。

操作选择只接收本轮原话与唯一绑定设备，不让历史目标或人物所在房间重新定义已绑定设备。明确房间不混入另一个房间的泛称别名。低分或相近分布先反问，阈值仍为概率至少 0.65、差值至少 0.2。

投喂和替代方案记录确切设备、能力与值，只能用有效的裸确认恢复。发言来源房间和目标房间独立记录；原地可以确认跨房间方案，换房间或 30 分钟上下文失效后不能沿用。含新要求的回复不是确认。相同请求 ID 重试不会重复投喂；红外“音量加”则允许不同请求再次按键。

高风险、敏感、配置、校准、重置、童锁等能力不因确认而解锁。数值无范围、越界、单位不匹配或步长不匹配时拒绝，不静默截断。服务接受但回读不匹配不算完成；按钮只能证明模拟触发/服务接受，不声称硬件物理结果已验证。

## 当前家庭的真实接口缺口

本机 HA 当前不可达，只能依据 2026-06-27 缓存判断接口和参考状态，不能当成在线事实。

- 空调已接入开关，但缓存未提供可靠温度边界。调温会拦截；在线只读同步提供范围后才可编译，不填默认范围来假装支持。
- 小爱音箱支持播放、暂停、音量、静音，没有停止播放接口。“停止播放”先问是否改为暂停，不改关机或其他按钮；确认后只模拟暂停。
- 电视缓存状态离线，原家庭回归断言其不执行；独立接口家庭验证红外按键可重复触发。
- 晾衣杆缓存仅电源开关，没有升降接口。原家庭不能模拟升降成功；测试家庭提供独立 cover 接口验证升降。
- 猫粮机缓存没有已确认的单次出粮动作，且显示离线。不会用校准按钮替代。投喂确认只在独立测试接口中验收。
- 当前缓存没有可识别的扫地机器人；清扫/停止/回充由独立测试接口验证，不向原家庭凭空增加设备。

三维反馈包括空调电源指示、风扇转速、窗帘开度、晾衣杆高度和模拟投喂标记；不是物理热学、照度、食物质量或实际清扫路径仿真。场景仍保留原家庭 12 个区域、45 台物理设备、43 个逻辑对象和 61 个设备点。

## 测试与体验

```bash
# 合成完整接口 + 局域网 D1，无 HA 连接
npm run test:d1:devices:live
# 附加当前家庭缓存接口，不读取 .env、不操作 HA
HARNESS_SANDBOX_SOURCE_DIRECTORY=/absolute/path/to/original npm run test:d1:devices:live
# 独立浏览器服务，不影响正在测试的页面
SANDBOX_DEVICE_FIXTURE=1 npm run test:sandbox:ha
# 可选：查看完整设备动作测试家庭，明确区别于自己的家庭
SANDBOX_FIXTURE=devices SANDBOX_PORT=5190 npm run demo:sandbox
```

当前家庭新版 Chrome 页面：`http://localhost:5186/sandbox.html`。可以测试“猫猫房风扇风速调到50%”“阳台左侧镜面纱开到30%”“客厅小爱音箱Pro音量调到25%”。查看设备详情中的“已接入操作”、HA 历史参考和模拟状态；查看房间不改变发言来源。

测试家庭可补测“书房空调调到24度”“降下客厅晾衣杆”“客厅扫地机器人回充”“客厅猫粮机投喂一次”，最后一条先询问，回复“可以”才模拟投喂。

本轮结果：**624 项单元测试通过、3 项在线测试跳过；57/57 新设备 D1 场景、53/53 原家庭语义回归、15/15 扩展家庭及 11/11 原家庭 Chrome 检查；构建通过。** 检查服务与参数、其他设备不变、确认边界、只读传感器、数值回读和桌面/平板/手机三维画布。57 组设备场景中位数 167ms、P95 704ms，包含多轮确认场景；不是 UI 延迟或 2 秒 SLA，也不是独立盲测准确率。

公开 [测试汇总](reports/d1-devices-v3.1-qa.json) 不含家庭名称、设备 ID、户型、状态或凭据。完整结果仅存本机忽略目录。测试期间发现磁盘空间不足造成 SQLite I/O 错误，已压缩可重复生成的测试轨迹；最终全量测试串行通过，没有关闭 SQLite 持久化或绕过安全门。
