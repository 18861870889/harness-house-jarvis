# D1 语义契约 v3

更新：2026-10-09。仅家庭沙盒默认启用；不替换主应用、Hermes 或历史框架比较。执行仍在原 HA 家庭目录的独立内存副本中进行。

## 原因与方案

v2 把完整开关方案交给 D1 选择，容易同时混淆意图、设备与数量。旧问题拼接新输入、换房间仍带旧目标、默认方案缺少“只开一盏”等语义，加上逐设备分数分散，造成相反操作或反复泛化澄清。模型分数高并不证明动作正确。

保留 Pi、SQLite journal、HCM、服务模拟和回读；使用 D1 原生多问题选择接口，不增加新的 agent 框架：

```text
当前原话 + 可信发言房间 + 同房间相关事实
  -> D1 一批语义字段：task / extent / feedback / target_form
  -> HCM 名称、别名、灯具类别和明确指代绑定
  -> 仍不明确时：有界 D1 目标选择或具体反问
  -> 混合开关时：逐目标的操作字段
  -> 数量、否定、能力、状态、范围校验
  -> HCM normalize -> provider simulate -> 内存 execute -> readback
```

所有有效业务输入先经过本地 D1，没有本地指令规划器或云模型兜底。直接名称通常只需一次调用；不明确目标或混合操作可能增加调用，不能声称全部单次。

参考已有的 [D1 Decision Model Guide](https://docs.liquid.ai/guides/decision-model-guide)、[HA intent slots](https://developers.home-assistant.io/docs/intent_builtin/) 和 [HA conversation response](https://developers.home-assistant.io/docs/intent_conversation_api/)。D1 在这里负责有界决策，不承担自由文本生成；回复来自已核验的家庭事实和执行结果。

## 模型与运行时边界

- 模型判断意图、数量范围、效果反馈和目标是泛称/具体名称/指代；不输出任意 HA 服务或任意设备 ID。
- 运行时绑定真实目录中的名称与房间。目录事实和最小改动策略不伪装成模型的 100% 置信度。
- 显式开/关、否定、只读问题和数量词约束决策 schema 与编译结果。规则只限定执行边界，不能绕过 D1 自行控制设备。
- 动作授权仍要求意图分数至少 0.65、差值至少 0.2；模型分布、字段、目标、数量和能力均需通过校验。没有通过降低阈值解决识别失败。
- “开一个灯”只改一个；“只开一个射灯”保证同房间最终仅一盏匹配射灯开启。已开灯的重复默认打开不逐次追加更多灯。
- “开射灯”不包含吊灯；否定子句排除对应设备。其他灯状态未知、只读或禁止操作时，不能谎称已保证“只留一盏”。
- 当前默认灯是稳定的主灯优先、同级按 ID 排序；增加/减少照明每轮作一个最小变化。不是个人偏好学习或强化学习。
- 未独立测量照度/舒适度。只能报告回路和能力事实，或询问用户是否合适；未知状态不当作关闭。

## 上下文与澄清

可信来源是后端校验的人物坐标/配置终端，不是查看房间下拉框或摄像机。明确房间优先；明确“它”可沿用上个目标；普通房间命令按新鲜来源。未知、门口、过期来源先澄清。

只传入同房间相关旧目标。新要求原话不与旧问题串接；旧待确认动作只在单纯同意、方案有效且房间范围相符时恢复。状态/能力查询和已满足命令也保留具体目标，后续“把它打开”仍可绑定。

“不要开吊灯”且吊灯已开时，先说明并询问是否关闭。“关闭的太多了”可基于上一条确实执行且仍关闭的同房间设备，提出精确的重新打开方案；不自动恢复，不把别的房间或仅预演的动作当作执行事实。含新要求或限制的回答不是裸确认。

轨迹文件的 v1/v2 是录制格式，`decisionVersion` 是决策契约，两者不同。回放只在独立基线副本中发生；若新版已不再询问旧问题，旧回复不会绑到别的待确认动作。回放“有差异”不等于新版错误，也不保证旧版意图正确。

## 验证

本轮 53/53 本地 D1 模拟回归组通过：18 轮用户交互加 1 次预热、29 个扩展场景、5 组追问序列。核对实际逻辑目标、对应回路、方向、动作数量、整屋最终状态和模拟写入数量，不只检查回答或模型分数。

扩展集覆盖独立开关、混合方向、连续否定、未接入灯具、只读状态/能力、过去状态查询、卧室歧义、指代无目标、位置询问、数量不支持、只留一盏、排除冲突、温度越界、状态未知、照明能力耗尽和确认后精确恢复。它是迭代后的回归集，不是独立盲测的通用准确率证明。

全量 Vitest：530 通过、3 个在线测试默认跳过。另有 Chrome 原家庭和合成家庭各 11 组端到端检查：画布非空、原户型完整、每个房间行走、输入不重建场景、正确书房回路、传感器无写入、隔离回放及桌面/平板/手机布局。

私人输入、户型、设备 ID、完整决策和前后快照只在被忽略的 `build/house-sandbox/` 保存，不提交。公开 [回归汇总](reports/d1-semantic-v3-house-qa.json) 只含统计与边界。


## 仍有限制

- 尚未验证在线 HA；本机参考状态是 2026-06-27 缓存，不能当成当前真实状态。
- 精确数量当前覆盖一台/一盏及只留一盏；其他精确数量先反问，不静默扩大执行。复杂多意图、澄清槽位补全和媒体/喂食等动作型技能还需扩展。
- 多房间“只留一盏”、禁止回路、无法可靠恢复的数值调整，不自动猜方案。
- 分数没有跨家庭校准；整轮硬延迟预算尚未验收。本轮观测不构成 2 秒 SLA。
- 浏览器 STT 可能联网；未测真实麦克风，尚无离线语音或真实室内定位。
- 未完成正式主链路迁移、个人偏好学习、长期沙盒存档、鉴权与真实设备 Pilot。

因此仍标记 Alpha，不因回归通过而宣布通用意图识别或真实设备发布完成。
