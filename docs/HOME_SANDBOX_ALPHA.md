# 家庭沙盒 Alpha

更新时间：2026-10-10。独立入口，不替代原控制页。**复用既有户型与 HA 目录；读取真实参考状态，执行只在模拟副本中发生。**

## 当前范围

Blender 制作可复用资产，Three.js 连续渲染，Rapier 处理人物碰撞；复用 Pi 会话、HCM 校验和内存执行，默认启用 [D1 语义契约 v3](D1_SEMANTIC_CONTRACT_V3.md)，不另写物理引擎。两房间样板仍保留供回归，配置家庭来源后使用原家庭数据，不重建另一套设备目录。

| 能力 | 当前实现 |
| --- | --- |
| 户型 | 读取原地图编辑数据，保留房间名称、矩形/多边形、合并区域和图片比例 |
| 设备 | 原 HCM 物理目录、逻辑灯具、房间分配、自定义名称及设备坐标 |
| 多键开关 | 安装位置与被控灯具房间分离，沿用具体回路，不按开关房间猜灯具 |
| HA 同步 | REST 状态 + WebSocket 注册表只读；30 秒轮询，手动刷新、最后良好快照 |
| 状态隔离 | HA 参考快照与模拟副本分别显示；新版快照由用户显式载入 |
| 房屋呈现 | 通用 Blender 家具与设备模型，动态组装原户型；不是实测装修复刻 |
| 行走与视角 | 地面点击寻路、键盘/方向按钮；旋转、缩放、平移、人物跟随 |
| 发言房间 | 后端从有效人物坐标推导，查看设备的房间或摄像机不改变来源 |
| 文字/语音 | 业务决策调用本地 D1；浏览器 STT、可选 TTS，无云端 LLM 兜底 |
| 意图与数量 | 分开判断意图、数量、反馈、目标表述；明确名称绑定 HCM，单盏/只留一盏、类别和否定逐项校验 |
| 澄清与追问 | 新要求不拼旧问题；只有单纯同意恢复精确方案，换房间隔离旧目标 |
| 非灯具动作 | v3.1 依据实际接口支持空调、风扇、窗帘、影音、升降、单次投喂与清扫，不由设备名称猜能力 |
| 执行反馈 | 内存执行与字段回读后更新灯光、空调指示、风扇速度、窗帘开度、晾衣杆高度及设备状态 |
| 数值与确认 | 数值范围/步长/单位核验；投喂精确确认，同意不整体解锁设备；无接口或范围未知先反问 |
| 只读传感器 | 读取快照及详情，不提供点击改状态，不随人物位置伪造 HA 检测 |
| 轨迹 | 最多 20 轮，紧凑 JSON，家庭基线校验和隔离回放 |

本机已保存家庭：**12 个区域、45 台 HA 物理设备、43 个逻辑受控对象、61 个场景设备点**。物理开关和被控灯具不是同一个计数单位。未分区对象仍保留在目录，不编造房间。

原书房映射为左键控制吊灯、中键控制射灯；未使用回路继续保护。入口开关控制餐厅灯的关系不受安装房间影响。映射来自既有 HCM/overlay，不写成全局固定左右键规则；旧样板的回路命名不同，仅用于样板回归。

当前原 HA 主机不可达，使用 **2026-06-27 的历史缓存**，页面标记来源、时间和错误。本轮未验证在线 HA 实时连接，不能将缓存状态当成当前真实状态。

当前缓存中空调缺少可靠温度范围、晾衣杆没有升降接口、猫粮机没有单次投喂接口，电视离线；这些情况仍会拦截。小爱音箱支持暂停但不支持停止，停止请求会询问是否改为暂停。完整接口只在独立测试家庭验证，不修改原家庭目录。能力表及测试方法见 [非灯具动作](D1_NON_LIGHT_DEVICES.md)。

## 数据与执行边界

```text
原项目保存的户型 + 命名/回路 overlay + HA 目录/状态（只读）
  -> 统一 HCM + 空间蓝图 -> HA 最新参考基线
  -> 显式建立独立模拟副本

人物坐标 + 文字/浏览器语音
  -> loopback /api/sandbox/command
  -> 坐标/来源校验 -> Pi 会话/同房间上下文
  -> 本地 D1 一批语义字段 -> HCM 目标绑定 -> 必要时有界目标选择/反问
  -> 非灯具动作/数值的有界操作选择
  -> 数量/否定/能力/状态/策略校验 -> 服务模拟 -> 内存 adapter -> 回读
  -> 模拟快照 -> Three.js / 设备面板 / 轨迹
```

- HA 传输层只允许 `GET /api/states` 和 WebSocket 的认证、设备/实体/区域注册表读取；拒绝 `call_service`、事件写入和其它路径。没有“真实执行”开关。
- 原目录 `.env` 只读取 HA 地址与令牌，不加载执行模式、云端 key 等其它变量。即使原项目配置 `HARNESS_EXECUTION_MODE=real`，本沙盒仍只模拟。
- 凭据不进入公开家庭快照、D1 上下文、日志状态或浏览器。配置、缓存和构建目录，包括 Vite 的 `@fs` 入口，禁止作为静态文件访问。
- 新同步结果不会覆盖已开始的模拟。载入新快照/重新开始会清空当前对话、轨迹与模拟状态，需确认；HA 本身不被修改。
- HA 离线时保留完整目录，也能重新读取本地地图编辑数据。已画出的房间不会因设备暂时为空或 HA 区域删除而消失；无效地图拒绝替换最后良好基线。
- API 和 HMR 固定监听 `127.0.0.1`，默认 5184 / 5284；Host/Origin 限制本服务，其他 `/api` 路径返回 404。这是本地开发入口，不是生产鉴权。
- Pi 会话/journal 暂存在本机临时目录 SQLite，正常关闭清理，异常退出可能残留。模拟设备仅在进程内存中，未提供长期存档。
- 模型分数不是校准正确率；低置信度澄清、安全策略和禁止回路仍生效。输入和候选方案不会提前改变场景，输入框也不会重建三维画布。
- 明确灯具名称通常一次 D1 请求；非灯具动作/数值通常增加一次操作选择，不明确目标或混合操作也可能增加调用。默认灯采用稳定的主灯优先策略，不是强化学习。静音、暂停、停止、电源和按钮按具体接口区分；没有唯一可信控制接口时反问。
- 红外/动作按钮记录每次模拟触发，不当作持久布尔开关；按钮服务接受不代表硬件结果已回读。数值字段不收敛不会报告成功，校准/重置/童锁/配置及高风险能力不因确认而解锁。

### 空间与回放

上传图的归一化坐标按图片比例投影。米制尺度目前估算，家具通用摆放，门洞由相邻区域推断；墙和家具使用 Rapier 碰撞，路线由可通行网格搜索，遇到不可达目的地不穿墙。

人物位置只模拟已配置语音终端的理想来源，不是现实定位算法。无效、屋外、墙内或家具内坐标在 D1 前拒绝；门洞或重叠区域位置不确定。明确房间优先，显式指代可延续旧目标，普通“开灯”按当前发言房间；新鲜但不明确的来源先澄清，不沿用旧讨论房间。

推理、语音采集与回放期间暂停人物移动。切换房间会清除 UI 旧问题绑定，新话题可主动清除绑定。查看房间设备只改变检查范围，点击脚印才实际走到该房间。

HA 副本轨迹的**录制格式**使用 v2，`decisionVersion` 另标记决策契约 v3；只保存请求、结果与位置，不重复附带大型家庭前后快照，绑定录制时的 `baselineId`。不同家庭/新基线、截断、重复请求、缺失确认前序或无效坐标在推理前拒绝；导入的 provider、凭据和设备快照不生效。旧样板录制格式仍用 v1。

回放重新建立独立初始副本、重新请求 D1，保持会话分隔和有效确认引用，结束后不改变当前世界。新版不再询问旧问题时，不会将旧回复绑定到另一个待确认方案。它是交互关键帧而非连续录像。“一致”比较结果状态及实际目标/能力/值，仅表示复现，不表示意图一定正确。

## 运行

需要 Node.js 24+、局域网 D1 与 WebGL 浏览器。普通运行不需要 Blender 或 Hermes。

```bash
npm ci
cp data/sandbox-source.example.json data/sandbox-source.local.json
# 在本地配置里填写原项目的绝对目录；baseUrl 可按需覆盖
npm run demo:sandbox
# Chrome: http://localhost:5184/sandbox.html
# 后台运行：npm run demo:sandbox -- --background
```

读取原目录的 `home_model_cache.json`、`data/home-model-overlay.local.json`、`data/spatial-editor.local.json`。`sandbox-source.local.json` 被 Git 忽略，私人户型、快照、凭据及完整测试轨迹不提交。

`HARNESS_SANDBOX_SOURCE_DIRECTORY` 可覆盖目录；`HA_BASE_URL`/`HA_TOKEN`（或 `HOME_ASSISTANT_URL`/`HOME_ASSISTANT_TOKEN`）覆盖连接。未设置环境令牌时从原目录 `.env` 读取。只读同步生成的缓存放在 `build/house-sandbox/ha-home.local.json`，不写回原目录。

默认 D1 为 `http://192.168.1.154:8080/v1/systemone`，`D1_ENDPOINT` 可覆盖；无需模型 API key。`SANDBOX_PORT` 默认 5184，`SANDBOX_DECISION_VERSION` 默认 v3，可显式设 v2 保留历史比较。日志与 PID 在 `build/house-sandbox/`；默认端口用 `server.log` / `server.pid`，自定义端口用 `server-<port>.log` / `server-<port>.pid`。后台重复启动先验证服务身份，不覆盖其他服务。

本次 Chrome 新演示在 **http://localhost:5186/sandbox.html**，保留原 5184、5185 服务及用户测试记录。普通运行仍默认 5184；已经运行的后端不会自动切换决策契约，先保存轨迹再重启，不能靠刷新网页升级。

未配置来源时运行旧两房间样板；`SANDBOX_SAMPLE=1` 显式选择样板，`SANDBOX_FIXTURE=1` 选择合成 HA 测试家庭，`SANDBOX_FIXTURE=devices` 选择扩展设备测试接口。配置了真实来源但快照/连接不可用时明确报错，不退回样板造成“房间变少”。

### 体验顺序

1. 在设备范围选书房，点击脚印，等待住户位置变成书房；输入“开一个灯”，应只改一盏；再输入“开射灯”，不应包括吊灯。
2. 输入“不要开吊灯”，若已开应先询问是否关闭；单纯回复“可以”只执行刚才的精确方案。输入“还是太暗了”只使用已有开关/调光能力，不应虚构非智能灯调光。
3. 查看别的房间并不改变来源；实际走过去后输入“开灯”，检查终端来源。明确设备名称可控制另一房间。
4. 查询目录中传感器的实际名称，检查无动作；点击设备详情对照 HA 参考快照和模拟副本。
5. 导出/回放轨迹；当前副本不受回放影响。更换基线后旧轨迹不能直接复用。
6. 同步 HA 目录，查看时间/错误；有新基线时显式载入，再测试。不要把“HA 历史快照”当成在线状态。
7. 输入“猫猫房风扇风速调到50%”“阳台左侧镜面纱开到30%”“客厅小爱音箱Pro音量调到25%”，查看详情中的模拟数值和已接入操作。只有参考快照存在相应接口时才可执行；不要用快照状态验证真机是否改变。

STT 可能使用浏览器外部服务，TTS 默认关闭。麦克风权限、实际音频硬件仍需人工验证；没有离线 STT/TTS 或唤醒词。刷新网页保留进程中的设备状态/轨迹，但人物回初始位置、页面聊天重新开始；重启或重新开始恢复参考基线。
