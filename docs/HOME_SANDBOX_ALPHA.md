# 家庭沙盒 Alpha

更新时间：2026-10-09。独立实验入口，不替代原控制页，也不接真实家庭设备。

## 本轮范围

先验证“住户在场景里发言 -> D1 决策 -> 模拟执行 -> 房屋反馈”的闭环。选择 Blender 制作资产、Three.js 实时呈现、Rapier 处理行走碰撞，复用现有 Pi/D1 v2 决策与 HCM 执行校验；不引入视频时间轴或另写物理引擎。

这是清爽风格的书房与客厅样板，**不是用户真实户型的精确复刻**。原地图、房间分配、真实 HA、原服务配置均保持独立。

| 能力 | 当前实现 |
| --- | --- |
| 房屋与人物 | Blender GLB，包含家具、灯具、住户；Three.js 连续渲染 |
| 视角 | 全屋旋转/缩放/平移、人物跟随，手机自适应 |
| 行走 | 地面点击、W/A/S/D、方向键、屏幕方向按钮；墙壁和家具碰撞 |
| 房间来源 | 后端校验人物坐标；书房/客厅模拟发言终端，门口位置不确定 |
| 文字 | 每条业务决策调用配置的本地 D1，无 DeepSeek 或云端 LLM 兜底 |
| 语音 | 浏览器 STT；低置信度保留文字待确认；可选浏览器 TTS，默认关闭 |
| 设备 | 书房射灯/吊灯、书房空调温度、客厅灯/亮度、电视、风扇、窗帘 |
| 可视变化 | 灯光与灯罩、电视屏幕、风扇转动、窗帘位置；空调温度显示在设备面板 |
| 轨迹 | 请求、人物坐标、结果、前后状态；导出 JSON、导入/当前轨迹隔离回放 |

书房两盏非智能灯分别映射到同一智能开关的左键、中键，未使用的右键保持禁止。客厅灯可调亮度，书房两盏灯仅支持开关，不虚构调光能力。

## 链路与隔离

```text
Three.js / 人物 / 文字或语音
  -> loopback /api/sandbox/command
  -> 坐标校验 -> 模拟发言终端
  -> Pi 会话 / 上下文 / D1 v2 单次完整选择
  -> HCM 意图、能力与策略校验
  -> 服务能力模拟 -> memory adapter 执行 -> 回读
  -> 状态快照 -> Three.js 与设备面板
```

- 后端固定创建 `createD1DemoAdapter` 的内存世界，不加载 `.env`，没有真实 HA 网络传输。即使主项目设置 `HARNESS_EXECUTION_MODE=real`，本入口仍只模拟。
- Pi 会话与执行 journal 临时写入本机临时目录的 SQLite，正常退出会清理；异常退出可能残留临时文件。它不用于长期恢复，不能把“设备内存模拟”理解成所有会话数据都从不落盘。
- HCM 中的 HA 风格 entity/service 签名是模拟能力契约，不代表连接 HA。其它 `/api` 路径返回 404；Host/Origin 限制为此服务的 loopback 地址。
- API 与 Vite 热更新监听均固定为 `127.0.0.1`，默认端口分别是 5184 / 5284，不向局域网开放。
- UI 不直接执行能力，D1 只选择有边界的方案，最终执行权限由确定性校验决定。模型分数不是经过校准的正确率。
- 只有执行器与回读更新设备状态；输入、候选方案、低分数提问都不会提前点亮灯具。三维场景不随输入框重建。
- 当前坐标是**模拟已配置麦克风的理想位置证据**，不是现实世界定位算法。后端拒绝屋外、墙内、家具内或无效坐标。
- 明确房间优先；“刚才那盏”可引用旧目标；普通“开灯”按当前发言房间。新鲜门口来源不会沿用旧讨论房间，位置不明确时澄清。
- 处理请求、语音采集和回放时暂停人物移动，避免同一轮发言位置漂移。中途换房间会清除 UI 的旧问题绑定，同房间另起话题可选择“新话题”。

### 状态查询修复

端到端测试发现，可控设备已有状态回读，但只读查询仅检索 `sensor` 字段而回答“暂无可读状态”。现在在没有单独传感器字段时，允许显示支持域中可控能力的实际布尔/有限数值状态；不显示未知、离线控制值，不把 `button` 的动作值当成状态。继电器控制的逻辑灯具仍保留“回路状态不是独立发光证据”的原有约束。

### 轨迹与回放

记录最多保留最近 20 轮；超过后标记 `truncated`，不允许把缺少开头的轨迹当成完整回放。重新开始可重新录制。

回放重新创建一份从初始状态开始的模拟房屋，重新请求 D1，保持原会话分隔并重映射确认引用。导入内容不能提供或替换设备 provider；无效坐标、重复请求、缺失确认前序、版本不兼容在推理前拒绝。

界面按回放结果展示人物位置和设备状态，结束后恢复当前世界。它回放的是**交互关键帧**，不是连续人物路径或视频。结果“一致/差异”比较状态码及实际目标/能力/值，只代表可复现性，不等于意图判断正确。

## 运行与体验

需要 Node.js 24+、可访问的局域网 D1，以及支持 WebGL 的浏览器。

```bash
npm ci
npm run demo:sandbox
# http://localhost:5184/

# 可选：后台运行，打印 URL 前会检查服务健康
npm run demo:sandbox -- --background
# 日志与 PID：build/house-sandbox/server.log / server.pid
```

`D1_ENDPOINT` 可覆盖默认的 `http://192.168.1.154:8080/v1/systemone`，`SANDBOX_PORT` 默认 5184。不需要 HA 地址/令牌、Hermes、模型 API key。后台重复启动会复用已确认的沙盒服务，不会覆盖其它占用端口的服务。

在 Chrome 中按下面顺序体验：

1. 人物默认在书房，输入“打开书房射灯”，观察对应灯具、灯光和设备行。
2. 输入“还是太暗了”，系统应选择补开吊灯；置信度不足时先问，回复“可以”后重新校验执行。灯具不支持调光时不会编造调光能力。
3. 点击客厅空地，经门口走到客厅后输入“开灯”，应控制客厅灯；视角切换不改变发言房间。
4. 输入“客厅灯现在开着吗”，只读查询不产生设备动作；再试电视、风扇、窗帘。
5. 点击麦克风，允许 Chrome/系统麦克风权限；点击播报图标开启 TTS。不支持 STT 或权限未开启时禁用/报错，不应伪装执行。
6. 在“场景轨迹”导出或回放；回放结束后当前房屋应保持原状。“重新开始”重置模拟设备、会话和轨迹。

地面点击使用经过门口的分段路线，不是全屋自动寻路；遇到家具会停下，可用方向键绕行。

语音识别可能依赖浏览器的外部服务。D1 本地免费不等于 STT 已完全离线；当前没有后台监听或唤醒词。真实麦克风、系统权限和扬声器体验需要人工验证。

刷新页面会保留服务进程中的设备状态和轨迹，但页面对话/人物回到初始位置并创建新会话；重启服务恢复初始房屋。这一阶段不提供长期存档。

## 资产重建

预生成的 `public/sandbox/house.glb` 和原创木纹 bitmap 已随仓库提供。普通运行不依赖 Blender。

```bash
npm run assets:sandbox
# 非默认安装路径：BLENDER_PATH=/path/to/blender npm run assets:sandbox
```

脚本从共享 `houseBlueprint.js` 几何生成房屋，输出 GLB、PNG，以及不入库的 `build/house-sandbox/house.blend`。Mac 默认路径是 `/Applications/Blender.app/Contents/MacOS/Blender`。Blender 在严格沙盒中可能无法初始化 Metal，应在允许本地图形运行的环境重建，不要因此修改模型逻辑。

使用现成官方能力的依据：[Blender glTF 导出](https://docs.blender.org/manual/en/5.2/addons/scene_gltf2.html)、[Three.js WebGLRenderer](https://threejs.org/docs/pages/WebGLRenderer.html)、[Rapier character controller](https://rapier.rs/docs/user_guides/javascript/character_controller/)。Three.js 承担实时交互；Remotion 是按帧驱动的视频工作流，暂不加入。[Remotion Three 文档](https://www.remotion.dev/docs/three)

| 验证 | 结果 |
| --- | --- |
| 全量 Vitest | 440 通过，3 个在线测试按默认配置跳过 |
| Adapter / Harness 子集 | 31 / 143 通过，已包含在全量计数中 |
| 构建 | 成功；Rapier/Three.js 初始资源包较大，仍有 chunk 大小警告 |
| Chrome 端到端 | 16 组通过，桌面 1440×1000、手机 390×844、平板 768×1024 |
| 启动边界 | 重复启动复用，异类服务占用端口时拒绝且不改已有 PID |
| 原 D1 严格多房间集 | 34/36，仍有两个保守澄清，不是全通过 |
| 原 D1 独立表达集 | 18/18 |
| 真实 HA / 麦克风硬件 | 未控制 HA；未验证真实麦克风硬件 |

本轮沙盒“打开书房射灯”完整 UI 检查耗时 863ms，其中 D1 请求 788ms；这是单机样本，不是性能 SLA。严格多房间集中的“还是太暗了”“这样好多了”仍需要澄清，保留原安全阈值，没有为了通过测试降低门控。

交付前另在用户 Chrome 验证了最终宽屏留白及桌面/手机/平板截图像素，修复宽屏外墙裁切；现场两轮灯光演示显示 648ms / 397ms，模拟回读与三维场景一致。完整记录保存在报告的 `finalChromeChecks`。

```bash
npm test
npm run test:adapter
npm run test:harness
npm run build
# 先启动沙盒；此脚本会重置且只操作沙盒
npm run test:sandbox:ui
```

Chrome 路径可通过 `CHROME_PATH` 覆盖，测试地址通过 `SANDBOX_TEST_URL` 覆盖，但仅允许 loopback 主机。浏览器测试阻止非当前服务源的 HTTP 请求；D1 推理由沙盒后端请求局域网模型。

测试脚本使用真实本地 D1 和内存设备，检查桌面/手机/平板截图、画布像素非空与灯光变化、人物移动、视角旋转、上下文指代、只读查询、设备动画、轨迹导入/导出、回放隔离和聊天画布稳定。语音测试注入浏览器事件，验证低置信度、权限拒绝、取消后的迟到结果、同步/迟到重复结果去重和 TTS，不录真实麦克风。

生成的截图、场景 JSON 和完整运行报告在 `build/house-sandbox/`。本轮实测汇总会保存到 `docs/reports/house-sandbox-qa.json`。

## 未完成与下一步

- 真实房屋复刻：用用户确认的户型与房间 ID 替换样板几何，资产挂载到既有 HCM，而非重建一套设备目录。
- 传感器模拟：PIR/人在传感器、检测延迟、误报/漏报、多人歧义和发言来源置信度。本轮人物位置不是传感器模拟。
- 扩展场景断言：用明确预期而非仅历史结果一致，覆盖故障、离线、跨房间和危险设备拒绝。
- 真实房屋与正式主界面集成：在独立沙盒验证充分后再做，不让实验世界覆盖现有户型。
- 离线 STT/TTS、唤醒词、真实多房间音频终端与长期存档尚未接入。

三维光照是可视反馈，不是真实照度、温度或人体舒适度仿真。D1 v2 历史严格回归仍有 2/36 条保守澄清，不以样板通过代替全量语义验收。现有依赖审计问题和生产部署鉴权尚未关闭，因此标为 Alpha，不能称为正式可发布版本。
